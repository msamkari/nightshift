# nightshift — بلجن لـClaude Code (الإصدار 0.1.6)

يكمّل عملك غير المنتهي وأنت غايب بدون ما يستهلك خطتك كلها. ملف طابور فيه بنود صغيرة، ومهمة مجدولة كل ساعة تنفّذ أول بند لم يكتمل محلياً وتسجّله وتتوقف. قبل كل تشغيل تفحص الاستهلاك وتتوقف إذا نافذة الـ5 ساعات 60% أو أكثر أو الأسبوعية 75% أو أكثر (تُعدَّل من ملف الطابور).

مهارات فقط: بلا سكربتات ولا كود شبكة ولا تثبيت.

## الاستخدام
1. `/nightshift:setup` — تقول له وش يكمل؛ يكتب `Jobs/resume_queue.md` ويعرض المهمة الساعية (لا تُنشأ إلا بعد «نعم» منك في المحادثة).
2. `/nightshift:run` — دورة واحدة؛ المهمة المجدولة تستدعيه، أو شغّله يدوياً لخطوة واحدة.

## اقرأ قبل تفعيل الجدولة
- **بلا مراجع.** التشغيل المجدول بدون إشراف وقد يستخدم وضع صلاحيات متساهل (مثل Bypass). «القواعد الصارمة» في الملف نص يتبعه النموذج وليست حماية تقنية: خلّ البنود صغيرة ومحلية.
- **مهارة التشغيل تحمل قواعدها بنفسها** (بنود داخل جذر المشروع فقط، لا تعديل لأسطر HARD RULES/LIMITS/Gate/STATUS في الطابور، قواعد الطابور لا تكون إلا أشد، وحد الاستهلاك لا يتجاوز 90%)، فحذف أو تخفيف «القواعد الصارمة» في الطابور لا يوسّع شيئاً. تبقى تعليمات لنموذج وليست عزلاً، ولم تُجرَّب بنموذج حي.
- **القفل العالق يوقف التشغيل.** إن كان `Jobs/.nightshift.lock` ملفاً أو junction/رابطاً أو غير فارغ أو بتاريخ مستقبلي فلا يزيله أي تشغيل: يتوقف ويكتب سطراً واحداً وعليك حذفه بنفسك.
- **الافتراضات متحفظة:** عمل محلي فقط؛ لا push ولا PR ولا دمج ولا نشر ولا إنفاق ولا تثبيت ولا تشغيل كود منزّل.
- **تكلفة الخمول.** تشغيل بلا شغل (STATUS DONE أو الاستهلاك عالٍ أو جلسة ثانية شغّالة) يفتح جلسة ويستهلك قليلاً.
- **مفتاح الإيقاف.** اكتب `STATUS: DONE` في ملف الطابور أو عطّل المهمة المجدولة. الطابور المنتهي يتوقف وحده.
- فحص الاستهلاك يحتاج أداة `get_usage` (تطبيق سطح المكتب). بدونها يتوقف عند أول رد حد استهلاك ويكمل التشغيل التالي.

## نوافذ الهدوء وترتيب البوابات (0.1.6)
- **سطر اختياري `QUIET_WINDOWS:`** في رأس الطابور (السطر 5 في القالب) بتوقيت الجهاز المحلي، مثال: `QUIET_WINDOWS: 08:30-09:20, 12:30-13:20`. الصيغة بالضبط `HH:MM-HH:MM` (24 ساعة، النهاية مستبعدة)؛ مدى مثل `23:30-00:30` يعبر منتصف الليل؛ والمدى يجوز أن يتداخل. داخل النافذة يتوقف التشغيل فوراً ولا يكتب شيئاً (لا سطر سجل ولا قفل): الأهدأ، وسطر السجل كان سيوقف التشغيل التالي بفحص الـ20 دقيقة. `none` أو قيمة فارغة أو غياب السطر يعني لا نوافذ، كما في 0.1.5.
- **القيمة الخاطئة تُغلق على الأمان:** التشغيل لا يفعل شيئاً ولا يكتب شيئاً ويقول في ردّه إن السطر خاطئ. أرقام مثل `830-920` أو شرطة طويلة أو `24:00` أو مدى بطول صفر أو سطران لـ`QUIET_WINDOWS:` كلها خاطئة. وإن تعذّرت قراءة الوقت المحلي مع وجود نوافذ لا يفعل شيئاً أيضاً.
- **ترتيب البوابات:** يقرأ التشغيل أول 15 سطراً فقط من الطابور (STATUS وLIMITS وQUIET_WINDOWS)، يفحص نوافذ الهدوء ثم الاستهلاك، وبعدها فقط يقرأ بقية الطابور وقواعد المشروع. عند التوقف للاستهلاك يقرأ آخر 10 أسطر فقط ليضيف سطر السجل المؤرخ الواحد. قراءة الرأس أولاً لا مفر منها لأن الحدود مكتوبة في الطابور.
- **إنهاء تلقائي:** إذا صارت كل البنود تحت `## Items` منجزة أو محجوبة يغيّر التشغيل السطر 2 من `STATUS: ACTIVE` تماماً إلى `STATUS: DONE` ويذكر ذلك. وإن كان السطر 2 غير ذلك (مسافات زائدة أو نص آخر) لا يعدّل شيئاً ويقول ذلك. التشغيلات الفارغة المجدولة تبقى تعمل حتى تعطّل المهمة.

## مع persistent-memory
إن وُجد `MDs/HANDOVER.md` وسجل Jobs يحدّثهما كل تشغيل آخراً (بعد الأرشفة)، وإلا يكفي ملف الطابور.

## الخصوصية
البلجن لا يضيف كود شبكة ويكتب داخل مشروعك فقط؛ المهمة المجدولة نفسها يخزّنها تطبيق Claude وكل تشغيل جلسة Claude عادية.
